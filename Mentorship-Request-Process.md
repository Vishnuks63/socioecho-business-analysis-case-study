# Process Mapping — Mentorship Request

## Primary Flow

1. Student identifies a guidance need.
2. Student logs into SocioEcho.
3. Student creates a mentorship request.
4. Student selects a guidance category and provides details.
5. System identifies/recommends relevant topics and mentors.
6. Relevant seniors/alumni view the request.
7. A mentor responds or accepts the request.
8. Student receives the response.
9. Mentorship continues through an appropriate communication/session mechanism.

## Exception Flow — No Suitable Mentor
If no suitable mentor is identified, the request can remain open and the student can be presented with relevant resources or future mentor recommendations.

> The exact business rule for an unmatched request should be confirmed with stakeholders before implementation.

## Process Analysis
The flow separates the student's need, requirement submission, matching, response and ongoing mentorship into identifiable process steps. This provides a basis for requirement validation and later change-impact analysis.
