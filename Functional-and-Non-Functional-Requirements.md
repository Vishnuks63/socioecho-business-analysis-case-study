# Requirements

## Functional Requirements

| ID | Requirement |
|---|---|
| FR-01 | Identify relevant topics/categories from a mentorship request. |
| FR-02 | Recommend relevant seniors/alumni based on skills, experience or expertise. |
| FR-03 | Recommend relevant resources based on request topics/categories. |
| FR-04 | Allow students to follow/connect with relevant seniors/alumni. |
| FR-05 | Allow students to create and submit mentorship requests. |
| FR-06 | Allow students to specify guidance categories and request details. |
| FR-07 | Allow relevant seniors/alumni to view and respond to requests. |
| FR-08 | Allow alumni to upload/share academic and career resources. |
| FR-09 | Allow authorized participants to create/join mentorship sessions. |
| FR-10 | Allow authorized organizers to publish events and opportunities. |

## Non-Functional Requirements

| ID | Requirement |
|---|---|
| NFR-01 | Key pages should load within an acceptable response time under expected usage. |
| NFR-02 | Personal information should be stored and transmitted securely. |
| NFR-03 | The system should support expected concurrent usage without unacceptable degradation. |
| NFR-04 | Only authorized users should access restricted mentorship sessions and management functions. |
| NFR-05 | The interface should be understandable and usable for the target student/mentor audience. |

## BA Principle Applied
Functional requirements describe **what** the solution does. Non-functional requirements describe **how well or under what constraints** it operates.
